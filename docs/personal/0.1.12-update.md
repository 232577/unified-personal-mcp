# 0.1.12 更新与运行核验

0.1.12 汇集本地分阶段诊断、完整工具指纹、服务端授权与显示标注分离、错误返回契约、命令观察和具名工作流接口。完整启用配置公布 58 个工具；减少启用能力的配置数量不同。

## 运行版本不是源码版本

源码修改和编译通过不代表已运行新版。连接后读取 `server_info`，核对 `version=0.1.12`、实际工具数量、`catalog_revision_format=complete-descriptors-v2` 与诊断状态。客户端目录可能仍需要由有权限的用户刷新；旧 UnifiedTask 等入口保留兼容。

## 本次发布修正

Windows 计划任务未找到错误可能位于 COM `EXCEPINFO` 的内部 HRESULT。只把真正的文件未找到识别成任务不存在；权限拒绝、账户信息缺失和其他错误继续失败，不自动覆盖登记。

COM 初始化改为明确的 CoInitializeEx；仅对本次成功取得的初始化引用执行 CoUninitialize。计划任务控制每次获取新的 COM 对象，仅字符串、数字和字典在调用边界间传递。演练仍检查任务所属用户、准确 XML、单实例策略以及运行和停止状态。

## 受控切换

维护脚本位于源码仓库 `scripts/switch_managed_release.py`，不是客户端绕过授权的接口。只有显式 `--arm` 才创建一次性、无周期触发器的维护任务。它会等待明确指定的本轮工作流结束；出现其他工作流、未知资源、登记变化或验证失败时，不强制结束其他任务。

本机维护可直接使用 `--run`，不传 `--allow-workflow-ref` 时要求零活动工作流，不创建一次性任务，也不需要构造工作流凭据。`--arm` 仍须明确指定本轮真实的非秘密工作流引用。

登记后的最后状态读取也纳入回退保护。切换使用安装器已经验证的 XML 收据；恢复登记前在同一次 COM 操作中再次比对当前 XML。等待进程退出期间出现外部登记变更时拒绝覆盖，保留冲突供机主处理。

候选包必须放在新目录，原包不覆盖。安装前校验全部文件摘要和隔离启动；准备停止服务时对工作流数据库取得短期事务锁，确认没有活动工作流，防止新的预约与停止步骤竞争。仅控制已有、归属明确的插件计划任务，不按任意 PID 强杀、不重启 Windows。

切换会短暂中断连接，不是内存热重载。新服务的本地核验失败时尝试恢复原登记和版本；若发现任务登记冲突或新业务工作，不冒险覆盖或强停，记录未完成状态，交由机主处理。

`LOCAL_READY` 仅表示本地服务与隧道健康检查符合预期，不证明 ChatGPT 已成功调用。必须再通过真实插件读取运行信息，并验证工作流、文件和命令操作。不能据此宣称所有安全拦截永久消失，或依赖零漏洞。

## 证据与隐私
