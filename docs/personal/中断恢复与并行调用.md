# 中断恢复与并行调用

适用于 0.1.6。先读取 `server_info` 的实际版本；安装包已更新不代表运行服务已切换。新版本包含 50 个工具，新增 OperationStatus 和 UnifiedTask resume；客户端若仍拒绝新参数或找不到新工具，应刷新插件工具目录。目录指纹 catalog_revision 用于核对，不能强制客户端刷新。

## 选择项目

每个独立项目使用自己的具体目录执行 UnifiedTask begin，然后 activate。不要为一个子项目占用整个 D:/run。调用共用构建脚本时保留业务项目工作目录，脚本使用绝对路径。完全控制模式允许跨目录，但不能自动解决共享文件、数据库及端口冲突。同一项目同时写入使用独立 Git 工作副本。

默认每个工作流最多运行 16 条命令；浏览器和搜索总额度可在配置中调整。前台键鼠输入仍只允许一个任务。server_info.resource_usage 给出当前资源计数、排队项目和等待时间；stale=true 表示元数据锁忙，返回了上一次快照。

## 调用中断后

1. 保留原 workflow_id 和 request_id。写请求必须有唯一 request_id，相同 ID 不得改参数。
2. 收到 OPERATION_RUNNING 时，用 OperationStatus 查询同一 request_id；后台仍运行，不要重新提交动作。
3. 收到 OUTCOME_UNKNOWN 或 BF_CALL_OUTCOME_UNKNOWN 时先读取真实文件、应用或业务状态。结果未知不代表操作没执行，不自动换 ID 重做。
4. 查询显示 completed/failed 时读取 result。失败的工具响应也保留原结果；unknown 不会自动重放。
5. 大结果超过 2 MiB 时保留已完成状态和带 SHA-256 的有界摘要。默认结果保留 24 小时、总计最多 64 MiB；结果淘汰后仍保留防重记录。最多 100000 条回执后拒绝新操作，错误为 OPERATION_CAPACITY；不会清除防重记录后偷偷重做。policy 以 server_info 返回为准。

BrowserActionStatus 等原有浏览器结果查询继续使用。OperationStatus 适用于记录在统一写操作日志中的请求，不替代浏览器专用接口。

## 令牌丢失，但需要继续原任务

先 UnifiedTask list，核对具体项目、workflow_ref、state=ACTIVE 和 credential_generation。仅在明确继续同一个任务时调用：

```json
{
  "action": "resume",
  "workflow_ref": "使用列表中返回的引用",
  "request_id": "本次接续的唯一标识",
  "expected_generation": 0
}
```

expected_generation 使用列表里的实际值，不能固定为 0。保存返回的新 workflow_id；旧凭证随后会被拒绝，但已进入执行的操作继续完成，命令标识和进程保持不变。接续响应丢失时，在 5 分钟内用完全相同参数重试即可取回同一结果，不会重复轮换。缓存过期或已被后一次接续替换时，重新 list 并核对后发起新的显式接续。

RESERVED、ENDED、CLEANUP_BLOCKED 等状态不能通过接续复活。主服务或电脑重启后，不承诺关机前的进程继续存在。PROJECT_BUSY 本身不是接管另一任务的授权。

## 长命令与取消

exec_command 的 yield_time_ms 控制本次等待多久，timeout_ms 控制命令允许运行多久。缩短等待不延长命令寿命。工作流 status 返回保留命令的 command_id、状态和输出引用。

write_stdin 的 chars 为空时轮询输出；非空时向命令输入内容。并行空轮询各自消费一段输出；独立回看请使用 read_output 的绝对 offset。kill_command 只取消本工作流拥有的 command_id，使用固定 request_id 重试以取回同一次取消结果。无法确认退出时保留 terminating 状态，不宣称已经停止。

桌面操作等待超时后，如果后台仍未结束或仍有归属明确的未知执行，同一工作流后续普通写入会返回 WORKFLOW_WRITE_PENDING，且不会分发该新操作。先查询原操作和连接状态，确认结束后再继续；状态查询、输出读取与命令取消不受这一写入拦截影响，其他工作流也独立运行。

## 连接和升级

隧道退出后按退避自动恢复；进程活着但网络暂不可用时保留隧道自身重连。密钥缺失、程序校验失败或归属不明会显示需要处理的错误。修复原密钥文件后可以从本程序控制窗口重新连接；已被服务继承的环境变量不会随外部修改刷新，改变其值或配置引用需要安排服务重启。

内部桌面连接退出后，下一次请求只在旧代次彻底结束后建立新连接；未完成的原生工作不会被新连接接管或重复执行。

完整便携包自带自启动管理。启用前校验 manifest、版本与隔离无隧道启动，失败保留旧任务；启用或取消不会主动停止当前服务。正常启用时间是下次登录 Windows。跨设备使用时重新配置该设备自己的隧道与密钥，不能让两台设备抢占同一个隧道。
