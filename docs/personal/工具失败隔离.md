# 工具失败隔离与结果观察

本次目标是减少单次失败对开发工作的连带影响，不是关闭平台安全检查。
候选目录有 53 个工具。源码、部署实例和客户端目录必须分别核验；本文件不是上线回执。

## 不同失败不能混为一谈

平台在分发前拒绝请求，本地服务可能没有收到任何内容。此时不能宣称请求执行失败、成功或已回滚，也不能通过改名、编码、换接口或更换 request_id 重放被拒绝的操作。

服务端已接收的参数错误、权限错误、执行错误和结果未知，使用各自的错误码。统一层错误返回现在有明确的输出 schema 分支：`ok=false` 和非空 `error.code`。不再为通过校验伪造文件正文、窗口列表或命令成功状态；原上游成功结果与原生错误结构保持不变。

本地对每个公开工具发送非法参数的测试，只证明本地错误契约与隔离性，不是对每个工具的真实业务执行验收，更不是模拟平台放行。

## 按工具类型处理

| 工具范围 | 失败后的处理边界 |
|---|---|
| 文件/Git/环境读取、窗口/页面观察及其他只读调用 | 保留旧结果但标明其时间；缺失新结果不能替代本次验收。无关且已授权的工作可继续；不得用其他通道重取被明确禁止的数据 |
| apply_patch、exec_command、write_stdin、kill_command 及有操作回执的桌面写入 | 对已经受理的请求查询 OperationStatus；保留原 request_id 和参数关联。unknown 不重做，过期结果不当作没有执行 |
| BrowserAction、BrowserNavigate、BrowserUpload、BrowserDownload 及有 request_id 的浏览器生命周期操作 | 查询原 BrowserActionStatus。会话/节点已过期时不能猜测新节点来重做未知操作 |
| UnifiedTask 生命周期 | 先观察工作流，再按真实 generation 恢复同一已授权工作流。重复 begin 不重新泄露一次性凭据；不接管其他项目 |
| SearchSession | 只在原所有者/搜索 ID 上读取或观察。没有搜索 ID 时不能假定未创建；保留现有配额和清理规则 |
| 结束/取消/清理 | 这些仍是有副作用的操作。失败时资源状态保持未知或保留，不把命令根进程退出等同全部资源结束 |

状态查询也必须经过平台和服务端检查，不承诺在任何情况下可用。依赖被拒绝步骤的后续动作应暂停；不能把未完成的检查改为通过。

## command_status：命令观察不再依赖标准输入接口

输入仅为当前有效 `workflow_id` 和既有 `command_id`。该工具不接受 cmd、chars、signal、request_id；不会执行命令、写入 stdin、消费输出游标、取消命令、续租工作流或新增执行回执。

- `observation=available`：成功观察到该工作流持有的句柄。
- `status=running`、`exit_code=null`：根命令仍在运行。
- `status=exited`、`exit_code=7`：根命令确实退出 7；这里的 `ok=true` 只是观察成功，不是构建或测试成功。
- 锁忙或查询异常：返回 `observation=unavailable`、`status=unknown` 和明确错误码，不阻塞等待输出。
- 句柄不存在：返回 COMMAND_NOT_FOUND；可能是过期、归属不同或没有登记，不能据此重跑原命令。

`stdout_ref` / `stderr_ref` 可供 read_output 按绝对偏移读取，不改变其他消费者的游标。`output_complete` 只说明根命令退出且读取线程已结束，不表示全部字节仍在保留区，也不表示后代进程已退出。后代与资源清理仍看工作流诊断。

## 已有结果与新写入分离

以前，同工作流存在未完成的原生操作时，已完成或已失败的命令/补丁回执也会被 WORKFLOW_WRITE_PENDING 遮挡。

现在，操作账本先检查相同请求的既有结果、参数冲突、运行中/未知和过期状态；只有真正的新请求才进入原生待决保护检查。保护仍在派发和新增回执之前执行。已受理请求丢失响应后的结果恢复不会重复产生副作用；这不是对平台拒绝请求的重试许可。

同一工作流存在可能未结束的原生写入时，新写入仍被挡住。其他项目的独立已授权操作不因这个工作流的待决状态而停止。没有放宽认证、工作流归属、写权限或副作用去重。

## 中文检索

本轮还复现了与安全提示不同的 search_text 内部错误：Windows 默认 GBK 解码不能正确读取 ripgrep 的 UTF-8 JSON。搜索子进程现在明确使用 UTF-8 解码；不修改系统区域设置、控制台代码页或文件编码。

## 上线和人工证据

候选代码需部署后，核对工具数、catalog_revision、diagnostics 与真实调用结果。现有运行实例不会因源码提交自动更新。平台提示是否消失仍是单独的发布阻塞项；本地测试成功不代替这一步。
