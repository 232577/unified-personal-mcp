# Unified Personal MCP

把编码、Windows 桌面、浏览器和 WebView2 操作放到同一个程序，通过 OpenAI Secure MCP Tunnel 连接自己的 Windows 开发机。

## 配置和运行

1. 将整个程序目录解压到本机较短的路径。双击 UnifiedPersonalMCP.exe。
2. 工作区填写多个项目所在的父目录。每次工作时选择其中一个具体项目。
3. 私有目录放在工作区以外，建议使用界面的默认值。
4. 填写本设备独立的 OpenAI 隧道 ID，选择运行密钥文件，或填写已配置的环境变量名。密钥内容不会显示。
5. 保存配置，运行“检查配置”，启动本地服务，然后连接隧道。

“代码操作权限”提供三个模式：限制执行、允许项目内执行、完全控制本机。前两个模式保持项目目录边界；完全控制本机允许跨目录读写、绝对命令目录与外部构建工具，权限等同启动本程序的 Windows 用户。仅在机主明确授权时选择。修改运行模式后需保存配置并重新启动服务；客户端可先调用 server_info 确认 permission_mode 为 full_control。

每台设备使用自己的私有目录、隧道和运行密钥。在两台同时运行的设备上不要使用同一个隧道 ID。配置界面会拒绝与本机正在使用的隧道竞争。

## 自动启动与连接

在本设备验证配置后，使用完整便携包窗口的“启用登录自启动”，或使用随包的 `scripts/install-autostart.ps1`。安装器先校验文件、指定版本和隔离启动，再修改计划任务，并保留原任务备份。指定实际运行包目录、版本和本设备配置文件：

```powershell
.\scripts\install-autostart.ps1 -BundlePath "X:\UnifiedPersonalMCP" -ConfigPath "X:\private\settings.local.json" -ExpectedVersion "0.1.6"
```

脚本创建 `UnifiedPersonalMCP-AutoConnect` 计划任务，在本 Windows 用户登录桌面 20 秒后后台启动本地服务并连接 OpenAI，无须再点击配置窗口。启动失败每分钟重试，最多 999 次；同一计划任务不重复运行。它复用本机密钥引用，不保存 Windows 登录密码、不配置自动登录，也不会立即停止或替换当前服务。首次安装使用你已经选定的运行包，升级包要由机主决定何时切换。

桌面控制需要交互登录会话；开机停在 Windows 登录界面时，这个任务尚不会运行。在另一台设备上重新配置后运行同一脚本即可。迁移运行包目录或切换版本后，重新执行脚本更新启动路径。可在 Windows 任务计划程序中禁用或删除该任务。

后台模式没有常驻配置窗口，重新打开程序可查看当前后台版本及下次登录版本。取消登录自启动只影响下一次登录，不终止当前项目。需要修改运行设置时，先结束工作流，再停止服务并保存配置。隧道遇到需要处理的错误，修正原密钥文件后可从窗口重新连接，也可在便携包目录执行 `./resources/python/python.exe -B -s ./app/run.py tunnel-retry --config "配置路径"`；此操作使用独立的本机控制凭证，不重启业务进程。服务已经继承的环境变量不会随外部修改刷新；改变其值或配置中的引用后，需要安排服务重启。

## 客户端工作流

先通过 UnifiedTask 的 begin 选择具体项目，保存仅返回一次的 workflow_id，再 activate。后续编码、桌面和浏览器工具使用同一个 workflow_id。结束时调用 end，释放本工作流的资源。

不同项目可并行执行，单个工作流最多同时运行 16 条命令。一个具体项目同时只能有一个写入工作流；需要并行修改同一项目时使用独立 Git 工作副本。已完成请求用相同 request_id 查询原结果；结果为 unknown 时先观察实际状态，不自动重做保存、启动或点击。

遇到 PROJECT_BUSY 时，查看 error.details.blockers 中的项目和 relation（same 同目录、ancestor 父目录、descendant 子目录）。UnifiedTask list 列出本账号会话及 workflow_ref。若已有令牌，继续使用原工作流；若遗失令牌且明确继续同一个 ACTIVE 任务，可使用 resume 和列表中的预期代次取得新凭证，保留已有进程。空闲无资源的会话也可在空闲期结束后使用 release_idle。具体错误处理见[中断恢复与并行调用](中断恢复与并行调用.md)。

默认 30 分钟无工具操作且没有运行资源后，服务自动回收会话。list 与 status 不续期，正常工具操作和 activate 会更新活动时间。运行中的命令、桌面操作、已启动应用、浏览器会话和搜索都会阻止空闲回收；状态无法确定时也保留。回收失败会保留目录租约与恢复信息，不能通过增加线程数解除。尚未 activate 的预留会话仍按原 ttl 到期。

配置窗口可调整空闲期（300～86400 秒）、浏览器会话数（1～32，默认 8）、WebView2 实例数（1～16，默认 4，不能超过浏览器总数）和搜索保留数（1～64，默认 16）。每个工作流最多一个浏览器会话、四个页面、一个受管理 WebView2 实例、两次搜索。前台键鼠操作共用一个输入位置，仍按租约轮流使用。修改后保存并重启服务，server_info.concurrency 显示实际额度。

## 工作目录与共用工具

工作流的 project_path 是默认项目。完全控制模式可选择项目父目录或其他本机已有目录；文件工具接受绝对路径和相对于默认项目的路径，exec_command 的 workdir 可指定绝对目录。每次命令的目录独立，不改变其他任务或后续文件工具的默认项目。

例如构建工具位于共用目录时，保持 workdir 为目标项目，使用 `node "X:/shared/build-binaries.js" "./deliver.config.js"` 这种显式调用方式。X:/shared 是示例位置，请替换为实际路径。共享工具按其文档接收目标项目参数，输出仍应指向要交付的项目。无须把工具源码复制进每个项目，也不依靠改解释器名称绕过检查。

要将 Git 查询、SearchSession、应用配置等默认上下文切换到另一个项目，应建立该项目的新工作流，结束不再使用的旧工作流。同一项目或父子目录的重叠写租约仍会拒绝；完全控制模式的跨目录命令与文件访问本身不提供共享资源隔离。

SearchSession 支持渐进搜索。stop 停止搜索并保留结果，release 停止并释放单次搜索及其结果，供后续搜索复用名额；无需结束整个工作流。每个工作流最多保留两次搜索，整台主机默认十六次，可在配置窗口调整。已完成搜索的保留结果不会阻止工作流空闲回收。

## 应用配置

项目目录中的 .bf/apps/*.json 注册应用。可使用相对于配置文件的路径，例如 project_root 为 ../..、启动文件为 ../../build/app.exe。示例见源码 examples/personal。

启动桌面应用使用 LaunchApplication；App 保留切换和调整窗口功能。浏览器会话使用 BrowserSession。附加 WebView2 仅支持已经启用本机调试通道、能够证明进程归属的已注册应用。结束附加会话不会关闭原应用。

优先使用窗口工具；需要前台输入时显式启用前台回退。最小化窗口截图可能使用临时恢复，截图不保证反映应用最新业务状态，应同时使用结构化观察验证。

## 停止、迁移和恢复

对于由当前配置窗口启动的服务，点击停止或关闭窗口会清理该服务拥有的资源。通过登录任务启动的独立后台服务不属于新打开的配置窗口；其停止按钮不可用，关闭窗口也不会停止后台服务和项目。清理未完成时会显示错误并保留恢复记录。重启后不根据旧 PID 终止进程。排障信息保存在私有目录。

将整个程序目录复制到另一台 Windows x64 设备后重新配置即可。不要复制原设备的私有目录、运行密钥、浏览器会话或配置文件。WebView2 应用需要该设备已安装 Microsoft WebView2 Runtime。

## 当前验证边界

本地 HTTP 与客户端经 OpenAI 隧道连接是两个独立检查。可用性与未完成项见项目 verification.md。公开仓库不包含本机密钥、运行配置、浏览器用户数据、截图或运行状态。
