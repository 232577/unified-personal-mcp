# 0.1.14 远程桌面

## 打开操控台

更新运行包后，在对应插件设置中刷新工具目录。完整服务的 server_info 应为0.1.14、63个接口，其中4个接口仅供组件调用。让助手在明确的项目工作流内打开 DesktopConsole；支持MCP Apps的客户端会显示侧边操控台。客户端不支持组件时，页面明确显示不支持，不使用假画面代替。

控制台默认仅查看。选择显示器或应用窗口，等画面加载，再开启“允许操控”。点击、右键、双击、滚动和拖动按图像像素映射到实际屏幕；文字通过下方输入框按字面发送，快捷键使用固定按钮。Escape、失焦、隐藏、断线以及30秒无输入会停止后续派发。已经送入Windows的事件无法撤回，释放按键/鼠标的清理仍执行。

Windows可能将非前台窗口的第一次点击只用于激活。请先看新画面，再操作具体控件。Windows拒绝焦点、窗口已移动、画面过期或被其他窗口遮挡时，服务会拒绝后续输入。不会通过关闭安全设置、跨安全桌面或重放未知动作解决这些拒绝。

结果未知时仅查询原操作回执。得到新的有效画面后，可选择“已检查画面，保持停止”；这不改变服务器的未知记录，不重发旧操作，也不自动开启操控。文件传输的未知结果必须查询传输/操作回执，不能凭画面确认。

## 已提供的能力

- 所选显示器或应用窗口画面；原生多显示器枚举，负坐标和DPI物理像素映射。
- 左/右/中键、单双击、字面Unicode输入、Ctrl/Shift/Alt与字母/数字/导航/F1–F12组合键。
- 按当前图像位置滚动；同一个窗口客户区内拖拽，输入最多约1秒且总是释放鼠标按钮。
- 用户主动读取或替换文字剪贴板；不自动同步剪贴板。
- 创建新文件的上传与文件快照下载，分块SHA256校验，不执行传输文件，不覆盖已有文件。
- 原有WindowControl后台控件接口继续保留；修复了右键/双击被当成普通Invoke、过期标签、焦点变化、UIA聚焦失败、Unicode计数与截图资源释放等问题。

## 文件与画面边界

单文件上限128 MiB、每块192 KiB、每工作流最多2项传输、有效期15分钟。上传父目录须已存在；safe/trusted模式不允许通过传输写入ignored/generated路径，full_control沿用机主选定的路径权限，但同样不允许覆盖或链接写入。下载需宿主支持组件保存接口；不支持时禁用该入口。宿主可能有更小的保存体积限制，应以实际客户端为准。

截图源最多24百万像素，预览长边最多1600像素、JPEG最多1 MiB；桌面画面只在内存与组件私有结果中传递。窗口捕获使用已核实坐标映射的PrintWindow；无法核实或应用不兼容时改选显示器画面。原WGC观察能力保留，但不会凭未知原点发送图像坐标输入。

这是自动刷新图像的远控方式，不是连续视频。默认刷新间隔1200毫秒，再加实际请求耗时，页面显示真实帧龄和往返耗时。画面有效期8秒；无效、过期或结果不明时停止新输入。跨窗口拖拽、标题栏拖动、Win键组合、安全桌面/UAC/锁屏以及无人登录前的操作不在本版支持范围。

## 隐私与兼容

操控台只得到短期组件凭据；原工作流、backend和tunnel密钥不进入页面。组件凭据随工作流结束、实际凭据轮换或到期失效，留在组件闭包内，不放URL/浏览器存储/日志。画面、剪贴板与下载数据放在工具结果_meta，公开结果只含状态和计量。

UI通过SDK的私有请求元数据调用原MCP入口，沿用本机认证及隧道，无新增公网HTTP/WebSocket端口。UI会话能力不是平台审批，也不是“物理用户手势”的密码学证明。真实宿主是否透传私有字段、支持侧边入口和保存文件必须分别验收，不能用本地模拟结果冒充。

源代码UI使用固定@modelcontextprotocol/ext-apps 2.0.3，离线bundle、源文件、锁文件和完整依赖许可证位于 personal_mcp/ui。构建：在独立临时目录复制package.json/package-lock.json/desktop.source.js，运行npm ci及npm run build，再将desktop.js回填；构建时去掉SDK原始消息console日志，不加载外部CDN。

## 升级

从本项目Release取得0.1.14源码升级ZIP和SHA256，解压到原安装目录之外，运行update.cmd。支持完整0.1.10、0.1.11、0.1.12、0.1.13作为基线；校验全部文件与依赖后新建同级0.1.14目录，再明确选择切换。旧包、配置和隧道密钥保留。升级包不是独立运行环境，不含第三方二进制。
