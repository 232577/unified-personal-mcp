## 已复现的问题

1. 对实际公开的 53 个候选工具发送非法额外参数，47 个上游工具的统一层错误对象不符合自身 outputSchema。失败列表保存在 verification/isolation-20261009-all-tools-first.log；不是 47 个工具全部执行失败，也不是平台后台结论。
2. 已完成/失败的命令或补丁回执、参数冲突，会被不相关的待决原生操作保护错误遮挡。4 个回归先失败；保留 WORKFLOW_WRITE_PENDING 对新写入的限制后，同组及相关账本/控制回归 26 项通过。
3. 命令观察没有独立只读入口；13 个新增回归先失败。实现后连同回执回归 17 项通过。
4. 本轮真实 search_text 调用返回 GBK 解码 INTERNAL_ERROR。使用真实固定版本 rg 与隔离中文路径/内容，强制 GBK 默认解码的回归先失败；不是安全拒绝，也没有修改系统代码页。

## 架构与代码复核

- 统一错误分支只接受 ok=false、error.code 及明确可选字段；不移除原上游正常结果的必填字段。当前目录已核验没有输出 $ref；后续接入引用型 schema 必须补充相应包装/解析测试，不能假定本次覆盖。
- 新 command_status 只访问当前工作流的内存句柄，不生成命令或写入数据。命令锁、输出锁采取非阻塞观察，忙时返回未知；不会把无记录当作已取消。
- 请求缓存返回仍在原有工作流归属/写权限检查之内。新增 before_dispatch 只允许有界本地检查，当前实现调用 drain(timeout=0)，不在数据库事务内执行原生命令或网络请求。
- 同工作流不明副作用保护保持；其他项目继续工作的测试只使用隔离文件，不操作真实桌面。
- 标准输入工具风险标注没有降低；查询入口不能用于改名重放被拒绝的写入。
- 原始错误 schema 和本地访问日志不是平台决策日志，不能声称已找到平台安全判定根因。

## 验证边界与执行问题

- 第一次基线命令未显式延长默认 30 秒限时，实际 timed_out=true、退出 15，日志仅部分输出，不计通过。后续套件显式使用有限的 600000ms 超时，保留全部断言；该超时是执行配置纠正，不是安全拦截重试。
- 一次多文件补丁的 README 行上下文不完整导致 PATCH_CONTEXT_NOT_FOUND；确认原子失败未改动前面的测试文件后，使用完整现有行重新提交补丁。
- 编码修复只有一行逻辑变更，但工具写入/Git 差异显示了整文件行尾差异。尝试了仅单条命令生效的 Git 文本规范化，没有更改全局配置；提交统计仍把该文件显示为整体差异。已另用两版本内容的逐行比较确认逻辑变化只有 encoding="utf-8"，不能把格式差异描述成数千行功能修改。
- 不运行真实截图测试 tests_bf/browser/test_frame_privacy.py；不调用桌面验收脚本。其源码和断言均保留，不计为通过。
- 不热替换生产、不改自启动、不重启宿主，不调用其他连接通道。
- 第一次导出逐工具矩阵时，发现复用的 full_control 最小夹具只有 43 个工具（未启用浏览器），而 trusted 夹具为 53；导出程序因此失败，没有生成虚假的双模式 53 工具报告。后续使用同样启用浏览器的隔离 full_control 配置，并断言确实有 53 个工具后重新全套验证。原 43 工具报告与失败记录保留。
